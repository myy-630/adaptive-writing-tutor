# 五维写作能力的过程性量表

`ObservableWritingRubric` 对学生在相应阶段提交的可观察材料给出 0–1 分。它不读取阶段的 `passed` 值，也不把通过/失败映射为 1/0。`StageGate` 将分数放进同一条 `LearningEvidence.rubric_score`，`StudentStateManager` 再按既有 EMA 公式更新对应能力。量表版本为 `observable-writing-v1`。

| 能力与评分时机 | 评分项及基础权重 | 具体取值 |
| --- | --- | --- |
| 审题；审题提交 | 文体匹配 0.35、必写要点覆盖 0.45、任务理解细节 0.20 | 文体与任务一致记 1；要点按覆盖比例计；细节按审题说明或“对象＋目的＋约束”的词数，18 词封顶。 |
| 语法；语法修改、最终评估 | 已识别模式准确度 0.60、已识别错误消除 0.40 | 准确度为 `1 / (1 + 修订稿中 Analyzer 识别的错误数)`；消除项为原稿错误类型计数中已消失的比例。最终评估使用 Draft 1 与 Draft 2。 |
| 结构；结构修改 | 段落组织 0.35、顺序标记 0.25、开头/主体/结尾计划细节 0.40 | 段落数达到 3 封顶；不同顺序或逻辑标记达到 2 个封顶；计划三个字段分别达到 8 词封顶后取平均。 |
| 内容；内容补充 | 新增内容词汇 0.35、题目要点的词面覆盖 0.30、五项内容计划细节 0.35 | 与上一稿相比新增的不同非停用词达到 10 个封顶；题目每个必写要点至少有一个内容词出现在稿件中即视为词面覆盖；计划五字段分别达到 8 词封顶后取平均。 |
| 句子表达；语言优化 | 实际表达修改 0.30、句间关系标记 0.30、关系解释 0.40 | 与上一稿相比修改的词达到 3 个封顶；不同连接或顺序标记达到 2 个封顶；关系解释达到 12 词封顶。 |

每项值都限制在 0–1。若题目没有必写要点、学生在独立模式没有填写隐藏的计划表，或原稿没有可消除的语法错误，对应评分项不计入，并把其余项权重归一化；不会把缺失项自动记为满分。没有可评分提交时，`rubric_score` 保持 `null`。初稿和二次重写阶段仍会记录原有学习证据，但没有本量表分数。

一次提交只评分其对应的能力维度；语法修改和最终评估分别提供一次语法证据。每条结果的 `score`、`dimension`、`version` 和各项 `value`、实际 `weight` 保存在 `workflow_events.stage_outcome.rubric`，同时其分数写入该事件的学习证据。稳定请求 ID 与证据 ID 保证恢复和重复提交不重复更新。学生状态使用 `new = ABILITY_EMA_ALPHA × score + (1 − ABILITY_EMA_ALPHA) × old`，默认系数为 0.3。若量表分恰好等于旧能力估计，显示百分比可能不变，但证据数和置信度仍增加。

## 适用范围与限制

这是可复核的过程性量表，数据只来自学生提交文本、作文任务、表单和当前 Grammar Analyzer。它不评价全文的思想深度、词语是否贴切或人工教师意义上的整体作文质量。词面匹配可能漏掉同义表达；词数、连接词和新增词汇可以被机械堆砌；语法项只覆盖 Analyzer 已实现的规则。因此这些百分比只能作为已检查特征的动态估计，不能充当考试分数或教学成效指标。DeepSeek 用于既有教学表达与教学质量评价，本量表不增加模型调用，也不把分数交给 Prompt 决定。历史无分数证据没有自动回填。

`tests/test_ability_rubric.py` 覆盖评分边界、空输入、异常、确定性和同门槛不同分数；`tests/test_module8_workflow.py` 用真实 PostgreSQL 贯通八阶段、证据、五维 EMA 与请求幂等。`scripts/demo_workflow_live.py` 通过真实 DeepSeek 工作流演示审题量表到 Student State 的更新。项目内自编样例不构成 Benchmark。
